# 查询拦截与人工预检联动

本页记录AI Agent升级后的实际代码，实习来源、合成数据和外部系统边界保持不变。

## 路由与预检

`fastapi-service/app/main.py` 在任何模型调用前判断敏感写意图。“执行同步/更新库存”等命令不进入模型执行工具，而是调用固定Java只读 `/api/sync/preview-read`。返回差异、来源SHA-256、业务版本与凭证卡片，库存和任务均不写入。固定库存/任务/就绪命令直达规则工具：`modelCalls=0, tokenUsage=0`。未命中的普通问题才进入最多5轮Function Calling；实际模型Token未采集时返回null，不虚构0。

operator卡片携带5分钟有效、绑定用户/业务日/来源摘要/版本的预检凭证；viewer只有差异与摘要，不获得凭证。凭证由编排分支直接返回页面，不交给LLM。Java执行端继续复核角色、人工确认、来源摘要、业务版本与幂等键，模型工具白名单仍只有只读。

页面点击“带入预检确认区”自动选择普通/刷新及来源任务，但确认框始终未勾选；用户核对后才能执行。带入不等于授权，SHA-256只证明被摘要内容一致，不证明外部来源天然可信。

## 重置与恢复

顶部“重置演示数据”只对operator显示。需明确确认、本机合成H2、没有运行中任务；单事务清理种子业务行/任务/样本并使用 `data.sql` 恢复80/40/120基线，保留并追加审计。业务revision递增，因此重置前的所有预检凭证失效。DDL仍在 `schema.sql`，不在重置事务里执行，避免H2隐式提交破坏回滚。

模型、viewer和未登录用户都不能调用重置。页面清除旧卡片与勾选状态，重置不会向外部系统写入。保留审计的重置事件没有runId，审计接口仍正常返回。
